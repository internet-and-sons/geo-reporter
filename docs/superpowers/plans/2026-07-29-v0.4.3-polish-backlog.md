### Task 1: Challenge fallback in `fetch_page()`

**The defect:** `is_challenge_page()` and the Playwright fallback exist but are wired ONLY into `probe_ai_crawlers`. `fetch_page()` (used by every content/technical/schema analysis) has no challenge handling — on a strict Cloudflare site it silently analyzes the block page as if it were content. During the zman.co.il eval the executor had to hand-patch the UA to proceed.

**Files:** Modify `scripts/fetch_page.py` (`fetch_page`); Create `tests/test_challenge_fallback.py`.

- [ ] **Step 1: Branch**
```bash
cd /Users/taloron/projects/ins-geo-reporter
git checkout main && git pull origin main && git checkout -b feat/v0.4.3-polish
```

- [ ] **Step 2: Write failing tests** — `tests/test_challenge_fallback.py`. Behavior contract:
  - `fetch_page()` result gains `"fetch_method"` (`"default"` | `"bot_ua_fallback"` | `"playwright"`) and `"challenge_detected"` (bool).
  - Normal 200 with real content → `fetch_method == "default"`, `challenge_detected is False`, one request made.
  - Baseline returns a Cloudflare challenge body (reuse a marker `is_challenge_page` recognizes, e.g. `"Just a moment..."` / `cf-challenge`) → the function retries once with the **GPTBot UA** (from `AI_CRAWLERS["GPTBot"]["ua"]`); if that retry returns non-challenge content, the result uses it, `fetch_method == "bot_ua_fallback"`, `challenge_detected is True`, and the content fields reflect the retry body.
  - Both attempts challenged → returns the best-effort parse of the last response, `challenge_detected is True`, `fetch_method == "default"`, and an entry in `errors` explaining the page could not be fetched as content.
  - A 403 that is NOT a challenge body → no retry (guard against retry storms), `fetch_method == "default"`.
  Mock `patch("fetch_page.requests.get")` with a side_effect list; assert call count for the retry cases.

- [ ] **Step 3–6:** Watch fail → implement (after the initial `requests.get` in `fetch_page`, test `is_challenge_page(response.text, response.status_code)`; on hit, retry once with `dict(request_headers, **{"User-Agent": AI_CRAWLERS["GPTBot"]["ua"]})`; only parse the better response; set both new fields; keep everything else identical) → full suite green (190 + N) → commit `fix: fetch_page falls back to a bot UA on Cloudflare challenge — challenged sites were analyzed as block pages`.

**Note for the skill layer (Task 4 consumes this):** `fetch_method == "bot_ua_fallback"` MUST be disclosed in report methodology — the analyzed content is what an AI crawler sees, which is the relevant view for GEO but is a material caveat.

### Task 4: Crawler-report consistency (address-verified rule + tier unification)

**Files:** Modify `skills/geo-botaccess/SKILL.md`, `skills/geo-crawlers/SKILL.md`.

- [ ] **(a) Address-verified-bot render rule** (geo-botaccess). Both live evals hit this and chose different (both legal) renders. Codify:

```markdown
### Address-verified crawlers — how to render (mandatory)

Googlebot, Bingbot, and the Google-* fetchers are verified by the CDN/WAF using the requesting **network address**, not the UA string. Our probe runs from the auditor's machine, so a 403 for these is the *expected, correct* anti-impersonation response and proves nothing about the real crawler.

Render them as `— Not tested (validated by network address — our probe cannot originate from the operator's network)` and add a follow-up task: verify in Google Search Console (URL Inspection → Test Live URL) and Bing Webmaster Tools. **Never** render an off-network 403 for these bots as `❌ Blocked` — that is a false alarm, and a Googlebot false alarm is an expensive one.

If independent evidence exists (e.g. the site appears in a `site:` search), cite it as corroboration that the real crawler is reaching the site.
```

  Also add the Task 1 disclosure rule: `If the page fetch used the bot-UA fallback (fetch_method == "bot_ua_fallback"), state in the methodology that content analysis reflects what an AI crawler receives, because the site's WAF challenges ordinary browser requests from scripts.`

- [ ] **(b) Tier-score unification** (geo-crawlers). The legacy Tier 1/2/3 scoring produced "AI Visibility Score 94/100" against a live 31/100 in the zman eval — two scores that disagree, bridged only by a hand-written sentence. Remove the legacy tier-derived score: delete the `## AI Visibility Score: [X]/100` block and its `Tier N Access` lines from the output template, and the `## Scoring for Crawler Access` weight table. Replace with: `**Crawler access score:** use the live probe's overall_score and class_scores (see geo-botaccess). This skill reports *declared policy*; the score comes from measured reachability. Do not compute a second score from tier counts — two scores that disagree confuse the reader (a permissive robots.txt with a blocking WAF is exactly the case that produces the contradiction).` Keep the tier *reference tables* (they document what each bot does) — only the scoring is removed.

- [ ] Verify + commit `feat: address-verified render rule; retire contradictory tier score in favour of measured reachability`.
